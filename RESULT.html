DotPad SDK 라이선스 표기 가이드

dotpad-sdk-guide 저장소(Android · iOS · Linux · Web · Windows)에 라이선스를 어떻게 정하고, 어디에, 어떤 문구로 표시할지 정리한 문서입니다. 2026-10-21 기준 저장소 내용을 직접 확인해서 작성했습니다.

참고: 이 문서는 실무 가이드이며 법률 자문이 아닙니다. 특히 SDK 이용약관(§4)과 iOS의 LGPL 대응(§6)은 공개 전에 법무 담당자나 오픈소스 전문 변호사의 검토를 받으시길 권장합니다.

1. 핵심 요약

  1. 라이선스를 두 개로 나눕니다. 이 저장소에는 성격이 다른 두 가지가 섞여 있습니다.
    • DemoApp 샘플 코드 · 문서 → Apache License 2.0 (개발자가 자기 앱에 자유롭게 복사·수정해서 쓰도록)
    • SDK 바이너리 (.dll, .aar, .xcframework, .a, .js) → DotPad SDK 이용약관 (무료로 쓰고 앱과 함께 재배포할 수 있지만 소스는 공개하지 않음)
  2. "오픈소스"라는 표현은 신중하게 써야 합니다. SDK 본체는 소스 없이 바이너리로만 배포되므로 OSI 기준의 오픈소스가 아닙니다. 대외 문구는 "무료 SDK + 오픈소스 샘플 코드"가 정확합니다. SDK 소스까지 공개할 계획이라면 전체를 Apache-2.0 하나로 통일하면 됩니다(§3 옵션 B).
  3. 서드파티 고지를 보완해야 합니다. 현재 라이선스 문서가 있는 것은 Web 3.0.2/3.0.3뿐입니다. Windows · Android · iOS도 liblouis(LGPL)를 포함하고 있지만 고지가 없고, iOS는 liblouis가 정적 링크되어 있어 LGPL 요건을 충족하려면 별도 조치가 필요합니다(§6).
  4. 루트에 LICENSE, LICENSE-SDK.md, THIRD-PARTY-NOTICES.md를 두고, README에 라이선스 섹션을 추가합니다. GitHub는 루트 LICENSE 파일을 읽어서 저장소 상단에 라이선스를 표시합니다.

LGPLv3+ 테이블은 Web README에 정리된 제외 목록(sr-g1.ctb, pt-pt-g2.ctb, Es-Es-G0.utb, et-g0.utb, is.tbl 등)과 같은 파일입니다. 제외 목록의 13개 파일이 Android · iOS · Windows 배포물에 모두 포함되어 있습니다.

3. 라이선스 선택

옵션 A (권장): 샘플·문서는 Apache-2.0, SDK 바이너리는 자체 이용약관

현재 배포 방식(SDK는 바이너리, 샘플은 소스)을 그대로 유지하는 경우입니다.

대상라이선스이유
*/DemoApp/**, README·가이드 문서, 이미지Apache-2.0상업 앱에도 자유롭게 복사할 수 있어 연동 장벽이 가장 낮음. 특허 허여 조항이 있어 하드웨어 회사에 적합하고, 상표권은 부여하지 않는다는 조항(§6)이 있어 "DotPad" 브랜드를 보호할 수 있음
SDK 바이너리, 헤더(DotSDKAPI.h, .d.ts 등)DotPad SDK 이용약관무료 사용·재배포는 허용하고, 역설계 금지·보증 부인·책임 제한을 명시
liblouis, MeCab, IPAdic 등각 원 라이선스 유지바꿀 수 없음. 고지 의무만 이행

옵션 B: SDK 소스까지 공개한다면 전체 Apache-2.0

SDK 소스까지 공개하는 진정한 오픈소스가 목표라면 저장소 전체를 Apache-2.0 하나로 두는 것이 가장 단순합니다. 이 경우 §4의 이용약관은 필요 없고, 서드파티 고지(§6)는 그대로 필요합니다.

MIT도 좋은 선택이지만, 하드웨어 프로토콜과 관련된 특허를 보유하고 있거나 보유할 가능성이 있다면 Apache-2.0이 회사와 사용자 모두에게 더 명확합니다. GPL 계열은 "더 많은 프로그램에서 연동"이라는 목적과 맞지 않습니다.

4. SDK 바이너리 이용약관 초안 (옵션 A)

아래는 LICENSE-SDK.md에 들어갈 핵심 조항의 뼈대입니다. 회사의 정식 법인명과 준거법은 법무 확인 후 기입하세요.

  1. 사용 허락: 닷패드 기기와 연동하는 소프트웨어를 개발·배포하는 목적으로, 무료·비독점·전 세계적으로 SDK를 사용할 수 있습니다. 상업적 사용도 포함합니다.
  2. 재배포: SDK 바이너리를 수정하지 않은 상태로 본인 애플리케이션에 포함해 재배포할 수 있습니다. SDK 단독으로 재판매하거나 SDK만 따로 배포하는 것은 허용하지 않습니다.
  3. 제한: 역설계·디컴파일·디스어셈블을 금지합니다. 단, 관련 법률이나 LGPL 등 서드파티 라이선스가 허용하는 범위는 예외입니다.
  4. 사용 대상 기기: Dot Inc.의 기기(Dot Pad 등)와의 연동 목적으로 한정합니다. (선택 조항이며, 확산이 목표라면 생략 가능)
  5. 서드파티 구성요소: SDK에 포함된 오픈소스 구성요소는 각각의 라이선스를 따르며, 해당 라이선스가 본 약관보다 우선합니다. (LGPL 준수를 위해 반드시 넣어야 하는 조항입니다)
  6. 상표: "Dot", "Dot Pad" 등의 상표·로고에 대한 권리는 부여하지 않습니다. "Works with Dot Pad"처럼 사실관계를 밝히는 표현은 허용합니다.
  7. 보증 부인 / 책임 제한: 현 상태 그대로(AS IS) 제공하며, 법이 허용하는 최대 범위에서 책임을 제한합니다.
  8. 해지: 약관을 위반하면 사용 권한이 자동으로 종료됩니다.
  9. 준거법·관할: 대한민국 법, 서울중앙지방법원 (법무 확인)

배포 zip 안에도 넣어야 합니다. 개발자는 저장소가 아니라 download/*.zip만 받아가는 경우가 많습니다. 각 zip(및 .aar, .xcframework) 안에도 LICENSE-SDK.md와 LICENSES/ 폴더를 넣어야 고지 의무가 이행됩니다. Web 3.0.3 zip이 이미 이렇게 되어 있으니 같은 방식을 따르면 됩니다.

플랫폼별 조치

우선순위 높음 iOS: liblouis 정적 링크 문제

DotPadFrameworks 바이너리 안에 liblouis 심볼(73개)이 들어 있습니다. LGPL은 사용자가 수정한 liblouis로 교체해서 다시 링크할 수 있는 수단을 요구하는데, 지금 구조로는 그게 불가능합니다. 해결 방법은 둘 중 하나입니다.

  1. (권장) liblouis를 별도 동적 프레임워크로 분리합니다. liblouis.xcframework를 따로 두고 DotPadFrameworks가 그것을 동적으로 참조하게 만듭니다.
  2. DotPadFrameworks의 오브젝트 파일(.o)과 링크 스크립트를 제공해서 사용자가 재링크할 수 있게 합니다. 사실상 SDK 내부 구조가 노출되므로 1번이 낫습니다.

참고로 App Store 배포와 LGPL의 충돌은 해석이 엇갈리는 영역입니다. 최종 앱 개발자에게 영향을 주는 사안이니 법무 검토를 권장합니다.

보완 필요 Android

  • liblouis.so가 별도 공유 라이브러리로 분리되어 있어 재링크 요건은 충족합니다.
  • LICENSES/liblouis-LGPL-2.1.txt를 추가하고, liblouis 버전과 소스 위치(GitHub 태그)를 README에 적습니다.
  • libjnilouis.so(JNI 래퍼)를 자사에서 작성했다면, Web의 liblouis-web/처럼 소스를 함께 공개하는 것이 안전합니다.
  • .aar의 assets/tables/에서 LGPLv3+ 테이블을 제외하거나, LGPL-3.0 전문을 추가합니다.

보완 필요 Windows

  • liblouis.dll은 DLL로 분리되어 있어 재링크 요건을 충족합니다. LGPL 전문과 소스 위치만 추가하면 됩니다.
  • MeCab은 "BSD 라이선스를 선택해 사용함"이라고 명시하고 BSD 고지문을 넣습니다.
  • ipadic.zip 안에 원본 COPYING이 들어 있는지 확인하고, 없으면 LICENSES/에 추가합니다.
  • tables.zip에서 LGPLv3+ 테이블을 정리합니다.

양호 Web: 3.0.2부터 갖춘 구성(LGPL 전문 + 래퍼 소스 + 빌드 스크립트 + README 고지)을 다른 플랫폼의 기준으로 삼으면 됩니다. liblouis.data 안에 Es-Es-G0.utb, pt-pt-g2.ctb라는 문자열이 남아 있는데, 실제 파일인지 다른 테이블의 참조인지 한 번 확인하세요.

구버전 처리 과거 버전 폴더

Windows 1.x~3.0.1, iOS 2.0~2.3.1, Android 1.1~3.0.2 등 이미 공개된 버전에도 같은 문제가 있습니다. 전부 다시 빌드할 필요는 없고, 각 버전 폴더에 LICENSES/만 추가하는 것으로 고지 의무는 상당 부분 보완됩니다. 더 이상 지원하지 않는 버전은 README에 "Deprecated"로 표시하세요.

7-6. GitHub 저장소 설정

  • 루트에 LICENSE(Apache-2.0 전문)를 두면 저장소 상단에 "Apache-2.0 license"가 표시됩니다. GitHub에서 Add file → Create new file → 파일명 LICENSE → "Choose a license template"을 쓰면 전문이 자동으로 채워집니다.
  • 저장소 About 설명에 "Free DotPad SDK with Apache-2.0 sample code"처럼 이중 구조를 한 줄로 밝혀 두면 오해를 줄일 수 있습니다.
  • 외부 기여를 받을 계획이라면 CONTRIBUTING.md에 "기여물은 Apache-2.0으로 제공된다"는 문구(inbound = outbound)를 넣습니다.
